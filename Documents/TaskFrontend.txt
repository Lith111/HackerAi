
# خطة عمل الفرونت إند مقسمة إلى 6 مهام (React Frontend)

**التقنيات:** React (Vite), Redux Toolkit, Tailwind CSS, React Router DOM  
**المبدأ:** بناء واجهة تفاعلية، داكنة المظهر، تعتمد على مكونات قابلة لإعادة الاستخدام، وتدعم التجاوب الكامل.

---

### المهمة 1: تأسيس المشروع والبنية الأساسية والثيم (Project Setup, Theme & Layout)

**الهدف:** إنشاء هيكل المشروع، تثبيت المكتبات، إعداد نظام التصميم (Tailwind) بالألوان العصرية، وبناء الهيكل العام للصفحات (Navbar, Footer, Layout) والتنقل الرئيسي.

**الدخل (Input):**
- توصيف التقنيات المطلوبة (Vite + React, Redux Toolkit, Tailwind CSS, React Router DOM).
- لوحة الألوان المحددة: خلفية داكنة (`slate-900`)، لون توكيدي سماوي (`cyan-400`)، ثانوي بنفسجي (`violet-400`) مع خطوط `Inter` و`Fira Code`.
- شعار افتراضي وأسماء الروابط الأساسية.

**الخرج (Output):**
- مشروع React يعمل محلياً مع Vite، و Tailwind مضبوط بالكامل.
- ثيم داكن متناسق، خطوط مهيأة.
- Router مُعد مع الصفحات الرئيسية الفارغة (Home, Auth, Dashboard...).
- هيكل تخطيطي (Layout) يحتوي على Navbar وFooter يظهران على جميع الصفحات.
- إعداد Redux Store (ولو فارغاً مؤقتاً).

**المهام التفصيلية (Checklist):**
1.  تهيئة مشروع Vite بقالب React.
2.  تثبيت `tailwindcss`, `postcss`, `autoprefixer` وتهيئة `tailwind.config.js`:
    - إضافة الألوان المخصصة (`cyber-cyan`, `cyber-violet` ...).
    - تمديد الإعدادات لتفعيل الوضع الداكن (`darkMode: 'class'` مع تطبيقها افتراضياً).
    - إضافة عائلة الخطوط `Inter` (للنصوص) و`Fira Code` (للكود).
3.  تثبيت `react-router-dom`, `@reduxjs/toolkit`, `react-redux`.
4.  إنشاء هيكل المجلدات (`components/`, `pages/`, `features/`, `layouts/`).
5.  بناء `AppRouter.jsx` مع مسارات الصفحات الرئيسية:
    - `/` (Home), `/login`, `/register`, `/dashboard`, `/lesson/:slug`, `/lab/:sessionId`.
6.  بناء `MainLayout.jsx` الذي يحتوي على:
    - `Navbar` (متجاوب مع قائمة همبرغر للجوال، شعار، روابط، أزرار CTA).
    - `Footer`.
    - مكون `<Outlet />` لتبديل المحتوى.
7.  إعداد Redux Store (`store.js`) وتجهيزه للشرائح المستقبلية.
8.  إضافة أنماط CSS عامة (مثل تأثيرات الزجاج `glassmorphism`، حركات بسيطة).
9.  التأكد من أن كل شيء يعمل بدون أخطاء وأن الصفحات تتنقل بينها بسلاسة.

### المهمة 2: صفحة الهبوط (Home Page) كاملة

**الهدف:** بناء الصفحة الرئيسية التي تضم جميع المعلومات عن المنصة، الفريق، وكيفية التسجيل، بتصميم جذاب بصرياً وعصري.

**الدخل (Input):**
- المحتوى المطلوب: قسم Hero، كيف تعمل، مميزات، فريق التطوير، FAQ، Footer.
- عناصر التصميم الموجودة من المهمة 1 (الألوان، الخطوط، التنسيقات).
- الصور والأيقونات (يمكن استخدام أيقونات SVG افتراضية أو مكتبة مثل `react-icons`).

**الخرج (Output):**
- صفحة Home مكتملة بكل أقسامها، متجاوبة مع جميع الشاشات.
- مكونات بطاقات (Cards) قابلة لإعادة الاستخدام.
- تأثيرات حركية خفيفة (مثل ظهور الأقسام عند التمرير - استخدام Intersection Observer يدوياً أو مكتبة خفيفة).
- أزرار توجه إلى صفحات التسجيل/تسجيل الدخول.

**المهام التفصيلية:**
1.  إنشاء المكونات القابلة لإعادة الاستخدام:
    - `SectionWrapper` (حاوية لكل قسم بعناوين وتباعد).
    - `GlassCard` (بطاقة بتأثير زجاجي وخلفية نصف شفافة).
    - `CTAButton` (زر بدعوة إجراء بتدرج لوني).
2.  بناء `HeroSection.jsx`:
    - خلفية متحركة (شبكة أو شيفرات تتساقط باستخدام CSS animation).
    - عنوان رئيسي كبير، فقرة وصفية، زران لاختيار المسار (أحمر / أزرق).
    - صورة أو رسم توضيحي (يمكن استخدام SVG inline).
3.  بناء `HowItWorksSection.jsx`:
    - 4 بطاقات GlassCard تصف الخطوات الأربع (تعلم، طبق، أخطئ، اتقن) مع أيقونات.
4.  بناء `FeaturesSection.jsx`:
    - شبكة من 3 أعمدة تبرز المميزات الفريدة (أسلوب التعلم التبايني، المساعد المؤقت، مسارين تخصصيين).
5.  بناء `TeamSection.jsx`:
    - بطاقات لأعضاء الفريق (صورة دائرية، اسم، دور، رابط).
    - تأثير hover يرفع البطاقة قليلاً.
6.  بناء `FAQSection.jsx`:
    - Accordion (قائمة أسئلة وأجوبة تفتح/تغلق).
7.  تجميع كل الأقسام في `HomePage.jsx` وضبط التجاوب (Responsive) باستخدام كلاسات Tailwind (`grid-cols-1 md:grid-cols-2 lg:grid-cols-4`).
8.  إضافة تأثيرات ظهور عند التمرير (Fade-in) باستخدام `IntersectionObserver` في custom hook.
9.  اختبار الصفحة على مختلف القياسات.

### المهمة 3: نظام المصادقة وتجربة المستخدم (Authentication & State)

**الهدف:** إنشاء صفحات تسجيل الدخول والتسجيل، ربطها بـ Redux وAPI الباك إند، وإدارة حالة المستخدم (مسجل/غير مسجل) لتنقل آمن.

**الدخل (Input):**
- نقاط API: `POST /api/auth/register/`, `POST /api/auth/login/`, `GET /api/auth/me/`.
- تصميم صفحة مقسمة (نموذج + رسم) من وثيقة الفرونت إند السابقة.
- Redux Store مهيأ.

**الخرج (Output):**
- شريحة `authSlice` كاملة في Redux تدير JWT والمستخدم.
- صفحة تسجيل دخول وتسجيل جذابة مع تحقق من صحة المدخلات.
- إعادة توجيه تلقائية بعد الدخول، وحماية المسارات (Protected Routes).
- Navbar يتغير تلقائياً (يعرض اسم المستخدم بدلاً من "تسجيل").

**المهام التفصيلية:**
1.  إنشاء `authSlice.js` في Redux Toolkit:
    - الحالة: `user`, `token`, `isLoading`, `error`.
    - Thunks غير متزامنة: `loginUser`, `registerUser`, `fetchCurrentUser` (باستخدام `createAsyncThunk`).
    - Reducers: `logout`.
2.  تثبيت `axios` وإنشاء `api.js` (instance مع baseURL ومُعترض لإضافة JWT للهيدر).
3.  بناء صفحة `AuthPage.jsx` بتصميم منقسم:
    - نصف أيسر: رسم توضيحي كبير.
    - نصف أيمن: نموذج تسجيل الدخول / التسجيل (يتبدل بينهما).
    - تأثيرات حركية لطيفة عند التبديل.
4.  بناء مكون `AuthForm.jsx` الذي يتعامل مع الحقول والتحقق (باستخدام React Hook Form أو Yup إن أردت، لكن يمكن بسيطاً باستخدام useState).
5.  إنشاء مكون `ProtectedRoute.jsx` يتحقق من وجود توكن، وإلا يعيد التوجيه إلى `/login`.
6.  تعديل `Navbar` لجلب حالة المستخدم من Redux: إذا كان موجوداً، عرض أفاتار وقائمة منسدلة (أو رابط للوحة التحكم)، وإلا عرض أزرار الدخول.
7.  توجيه المستخدم بعد تسجيل الدخول إلى `/dashboard` (أو الصفحة التي كان يحاول الوصول إليها).
8.  اختبار سيناريوهات: تسجيل خاطئ، تسجيل صحيح، استمرار الجلسة بعد تحديث الصفحة (باستخدام التوكن من `localStorage` وتحميل المستخدم).

### المهمة 4: لوحة التحكم وعرض الدروس والتعلم التسلسلي (Dashboard & Lessons)

**الهدف:** بناء واجهة الطالب الرئيسية بعد الدخول، حيث يشاهد مساره والدروس المتاحة وحالة التقدم، وصفحة عرض الدرس الفردي بأقسامه الأربعة مع إظهار الكود البرمجي وآلية التنقل بين الأقسام.

**الدخل (Input):**
- نقاط API: `GET /api/courses/`، `GET /api/courses/{slug}/`، `POST /api/progress/lessons/{id}/complete-block/`، `GET /api/progress/`.
- صلاحيات المستخدم.
- وصف الأقسام الأربعة للدرس.

**الخرج (Output):**
- صفحة Dashboard تعرض ترحيباً، شريط تقدم عام، وقائمة دروس (مع أيقونات قفل/فتح/إكمال).
- صفحة Lesson تحتوي على شريط تقدم داخلي لأقسامه الأربعة، ومحتوى الكتلة الحالية (نص وكود) مع زر "التالي" الذي لا يظهر إلا بعد الوصول إلى نهاية الكتلة الرابعة.
- مكون عرض الكود (Code Viewer) بتنسيق جميل وخلفية داكنة وترقيم أسطر وهمي.
- تفاعل مع Redux لتحديث التقدم فوراً.

**المهام التفصيلية:**
1.  إنشاء `coursesSlice.js` و`progressSlice.js` (أو شريحة واحدة) لإدارة بيانات الدروس والتقدم.
2.  بناء صفحة `DashboardPage.jsx`:
    - صف تحية: "مرحباً، [اسم المستخدم]!" مع مساره (Red/Blue).
    - بطاقة نسبة الإنجاز (Progress Bar دائرية أو خطية).
    - قائمة الدروس (بطاقات صغيرة) لكل درس: عنوان، حالة (مقفل بقفل، مفتوح بسهم، مكتمل بعلامة صح). عند النقر، ينتقل إلى `/lesson/:slug`.
    - لا يمكن للمستخدم فتح درس مقفل.
3.  بناء صفحة `LessonPage.jsx`:
    - شريط علوي صغير يوضح اسم الدرس وأقسامه الأربعة (دوائر مرقمة)، تُملأ عند الإكمال.
    - منطقة عرض المحتوى الرئيسية:
        - إذا كانت الكتلة من نوع `VULN_THEORY` أو `DEFENSE_THEORY`: عرض النص باستخدام Markdown (مكتبة `react-markdown`).
        - إذا كانت `EXPLOIT_CODE` أو `SECURE_CODE`: عرض الكود في مكون `CodeBlock` مع صندوق داكن، وتنسيق تلقائي.
    - زر "التالي" (يظهر إذا كانت الكتلة الحالية هي الأخيرة، أو بعد أن يقر الطالب أنه فهم المحتوى). عند الضغط:
        - إذا لم تكن الكتلة الأخيرة، ينتقل للكتلة التالية داخل الدرس.
        - إذا كانت الكتلة الرابعة، يستدعي `complete-block` API للكتلة الأخيرة. سيتحقق الباك إند ويكمل الدرس.
    - إظهار رسالة "لقد أنهيت الدرس!" وإعادة التوجيه إلى Dashboard.
4.  بناء `CodeBlock.jsx` مع تنسيق باستخدام `prism.js` أو `highlight.js` أو حتى تنسيق بسيط يدوياً، مع زر نسخ.
5.  تطبيق منطق التسلسل: في Dashboard، الدروس التالية تُعرض مقفلة بناءً على `is_locked` القادم من API.
6.  التأكد من أن التقدم ينعكس في الواجهة فوراً عند إكمال درس (تحديث Redux بعد الطلب الناجح).

### المهمة 5: مختبر التيرمنال والذكاء الاصطناعي (Terminal Lab & AI Integration)

**الهدف:** بناء واجهة محاكاة التيرمنال كاملة، مع الاتصال عبر WebSocket، وعرض المساعدة المؤقتة بمؤقت 10 ثواني، والشات بوت المنبثق.

**الدخل (Input):**
- نقاط API: `GET /api/lab/scenarios/`, `POST /api/lab/scenarios/{id}/start/`, `ws/terminal/{session_id}/` (WebSocket), `POST /api/ai/chatbot/`.
- منطق الأوامر والمساعدة من وثيقة الباك إند.
- مكتبات: `xterm` (للتيرمنال)، `socket.io-client` أو `WebSocket` الأصلي.

**الخرج (Output):**
- صفحة `LabPage` تبدأ باختيار سيناريو، ثم تنطلق الجلسة.
- واجهة تيرمنال وهمي باستخدام `xterm.js` أو محاكاة أبسط تعمل عبر WebSocket.
- آلية إرسال الأوامر وعرض النتائج، مع عرض "help_available" وظهور مساعدة مؤقتة.
- عند الموافقة على المساعدة، يظهر صندوق منبثق مع النص ومؤقت تنازلي 10 ثواني، ثم يختفي ويعاد تعيين الجلسة.
- شات بوت (زر عائم) يمكنه الإجابة على الأسئلة العامة.

**المهام التفصيلية:**
1.  تثبيت `xterm` و `xterm-addon-fit` (للتكيف مع حجم الحاوية). ضبط `TerminalComponent` باستخدام `useRef` وتهيئة `Terminal` عند تنفيذ `useEffect`.
2.  إنشاء `labSlice.js` يدير `sessionId`, `outputs`, `helpData`, `isConnected`.
3.  بناء صفحة `LabPage.jsx`:
    - إذا لم توجد جلسة، عرض قائمة السيناريوهات (بطاقات) وبدء جلسة بالضغط (استدعاء `POST start` لاستقبال `sessionId`).
    - بعد البدء، عرض التيرمنال وشريط جانبي للتعليمات.
4.  إدارة WebSocket في `useEffect`:
    - فتح اتصال `ws://.../terminal/{sessionId}/` مع إرسال التوكن.
    - استقبال الرسائل: إذا `type: "output"` يكتب إلى الـ terminal باستخدام `term.write`.
    - إذا `type: "help_available"`، تفعيل حالة `canRequestHelp`.
    - إذا `type: "show_help"`، عرض مساعدة مؤقتة (نافذة منبثقة).
5.  إرسال الأوامر: عند كتابة المستخدم أمراً في الـ terminal، يتم التقاطه (باستخدام واجهة xterm) وإرساله كرسالة JSON عبر WebSocket: `{"command": "..."}`.
6.  بناء مكون `HelpPopup.jsx`:
    - عند وجود `helpData`، إظهار نافذة عائمة تحتوي على النص.
    - مؤقت تنازلي مرئي (10 -> 0) باستخدام `useEffect` مع `setInterval`. عند الوصول إلى 0، إخفاء النافذة وإرسال أمر `{"action": "reset_session"}` إلى WebSocket.
    - مسح الـ terminal واجهةً عند إعادة التعيين.
7.  بناء مكون `Chatbot.jsx`:
    - زر عائم في الزاوية السفلية اليمنى.
    - عند النقر، فتح نافذة محادثة (دردشة) ترسل عبر `POST /api/ai/chatbot/` وتعرض الردود.
    - تخزين سجل المحادثة في حالة محلية.
8.  اختبار السيناريو كاملاً: كتابة أمر صحيح، أمر خاطئ، قبول المساعدة، انتهاء المؤقت.

### المهمة 6: الاختبارات، التلميع النهائي والاستعداد للإطلاق (Testing, Polish & Deployment Prep)

**الهدف:** تحسين الأداء، إضافة الحركات الناقصة، تلميع التفاصيل البصرية، كتابة اختبارات واجهة (إن أمكن)، وإعداد المشروع لبنائه للإنتاج وربطه بالباك إند المنشور.

**الدخل (Input):**
- المشروع شبه مكتمل.
- ملاحظات من تجربة الاستخدام.
- بيئة الإنتاج (قد لا تكون جاهزة بعد، لكن يتم إعداد كود البناء).

**الخرج (Output):**
- واجهة مصقولة، متجاوبة تماماً، بدون تشوهات.
- تحسينات سرعة (تقسيم الكود Lazy Loading).
- تقارير اختبار (اختبارات مكونات بواسطة Vitest أو يدوياً).
- بناء إنتاجي (Production Build) جاهز للنشر.

**المهام التفصيلية:**
1.  **تحسين الأداء:**
    - تطبيق `React.lazy` و `Suspense` على تحميل الصفحات (Home, Dashboard, Lab...).
    - ضغط الصور واستخدام صيغ حديثة (WebP).
    - التأكد من عدم إعادة تحميل المكونات بدون داعٍ (React.memo).
2.  **إضافة الحركات والانتقالات (Micro-interactions):**
    - استخدام `Framer Motion` أو `Tailwind Animate` لحركة دخول/خروج الصفحات.
    - تحسين تأثيرات hover على جميع البطاقات والأزرار.
    - إضافة تأثير تحميل (Skeleton Loaders) أثناء جلب البيانات من API لتحسين تجربة المستخدم.
3.  **التجاوب الكامل (Responsive Polish):**
    - فحص جميع الصفحات على شاشات الجوال والجهاز اللوحي وسطح المكتب.
    - إصلاح أي تخطيطات متكسرة، تعديل أحجام الخطوط والمسافات.
    - التأكد من أن قائمة الهامبرغر تعمل في الجوال.
4.  **الاختبارات (Testing - اختياري لكن مهم):**
    - كتابة اختبارات وحدة لمكونات رئيسية (مثل `CodeBlock`, `GlassCard`).
    - اختبار تدفق المصادقة وتخزين التوكن.
    - اختبار اتصال WebSocket باستخدام محاكي.
5.  **الأمان والتهيئة النهائية:**
    - التأكد من أن مفاتيح API لا تظهر في الكود الأمامي (كل شيء عبر الخلفية).
    - إضافة `meta tags` للـ SEO في `index.html`.
    - إعداد متغيرات البيئة (مثل `VITE_API_BASE_URL` و`VITE_WS_URL`) لاستخدامها في axios و WebSocket.
6.  **بناء الإنتاج والنشر الأولي:**
    - تشغيل `npm run build` والتأكد من عدم وجود أخطاء.
    - معاينة البناء محلياً (`vite preview`).
    - وضع تعليمات لنشر المجلد `dist` على Nginx أو Vercel/Netlify.
    - إعداد إعادة توجيه جميع المسارات إلى `index.html` ليتولى React Router التحكم.
7.  **توثيق المكونات الرئيسية في ملف README للفرونت إند.**
